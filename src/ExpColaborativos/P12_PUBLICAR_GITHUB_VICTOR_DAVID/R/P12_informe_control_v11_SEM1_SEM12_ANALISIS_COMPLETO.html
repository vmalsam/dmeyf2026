Para qué sirve este documento

Este es nuestro informe interno de control y comprensión del P12. No es la presentación de YouTube ni pretende volver a ejecutar el experimento.

El trabajo pesado sigue ocurriendo donde corresponde:

Jupyter + LightGBM + Grid Search + Kaggle
                  |
                  v
            scripts Python
                  |
                  v
             90_RESULTADOS
                  |
                  v
      ESTE INFORME R MARKDOWN
                  |
                  v
        tablas + gráficos + control

La idea es simple: cada vez que aparezcan nuevos resultados consolidados en 90_RESULTADOS, hacemos Knit nuevamente y el informe se actualiza solo.

El documento no vuelve a calcular el score de Kaggle ni modifica notebooks, modelos, parámetros o submissions.

1 Pregunta del experimento

El Problema #12 estudia:

¿Hasta cuánto podemos reducir los registros utilizados mediante undersampling sin deteriorar de manera relevante el comportamiento predictivo y económico del modelo?

Los cinco escenarios son:

Código Escenario Interpretación
B100 100% Baseline
U040 40% Conserva aproximadamente 40% de CONTINUA
U010 10% Conserva aproximadamente 10% de CONTINUA
U005 5% Conserva aproximadamente 5% de CONTINUA
U001 1% Conserva aproximadamente 1% de CONTINUA

BAJA+1 y BAJA+2 se conservan completas. El porcentaje de undersampling se aplica sobre la clase CONTINUA; por eso el porcentaje real total conservado queda algo por encima del porcentaje nominal.

Las distintas semillas son réplicas del mismo experimento. Victor y David no representan experimentos distintos: las semillas de ambos ya están integradas en un único análisis SEM1..SEM12.

2.1 Qué parte del notebook define el escenario y la semilla

En la celda de configuración del notebook se define la réplica que estamos ejecutando.

Ejemplo:

P12_SEMILLA <- 198427

P12_ESCENARIO <- "BASELINE_100"
P12_TRAINING_PCT <- 1.00
P12_CODIGO_ESCENARIO <- "B100"

PARAM$semilla_primigenia <- P12_SEMILLA
PARAM$experimento <- paste0(
  "P12_",
  P12_CODIGO_ESCENARIO,
  "_S",
  P12_SEMILLA
)

Para el P12, lo que cambia entre escenarios es principalmente:

P12_TRAINING_PCT

con los valores:

1.00
0.40
0.10
0.05
0.01

La semilla cambia entre réplicas.

2.2 Qué parte del notebook aplica el undersampling

En la sección Training Strategy el notebook lleva el porcentaje del escenario a:

PARAM$trainingstrategy$training_pct <- P12_TRAINING_PCT

Luego se construye fold_train.

El bloque fundamental es:

set.seed(
  PARAM$semilla_primigenia,
  kind = "L'Ecuyer-CMRG"
)

dataset[, azar := runif(nrow(dataset))]

dataset[
  ,
  fold_train :=
    foto_mes %in% PARAM$trainingstrategy$training &
    (
      clase_ternaria %in% c("BAJA+1", "BAJA+2") |
      azar < PARAM$trainingstrategy$training_pct
    )
]

Este es el punto concreto donde se produce el undersampling.

Interpretación:

BAJA+1 y BAJA+2  -> se conservan
CONTINUA         -> queda según training_pct

Por eso un escenario 10% significa aproximadamente 10% de CONTINUA, no 10% de todo el dataset.

2.3 Qué parte del notebook cuenta los registros antes y después

Inmediatamente después de crear fold_train, nuestras versiones finales del notebook guardan el efecto real del undersampling dentro de:

PARAM$p12$registros

El bloque contiene, entre otros:

PARAM$p12$registros$training_antes <- dataset[
  foto_mes %in% PARAM$trainingstrategy$training,
  .N
]

PARAM$p12$registros$training_despues <- dataset[
  fold_train == TRUE,
  .N
]

PARAM$p12$registros$porcentaje_real_conservado <- round(
  100 *
  PARAM$p12$registros$training_despues /
  PARAM$p12$registros$training_antes,
  4
)

También quedan registrados:

positivos_antes
positivos_despues
negativos_antes
negativos_despues

Estos datos después llegan al PARAM.yml.

2.4 Qué parte del notebook calcula AUC y busca los hiperparámetros

El notebook define primero los parámetros fijos de LightGBM.

Entre ellos:

max_bin = 31
learning_rate = 0.03
feature_fraction = 0.5
num_iterations = 2048
early_stopping_rounds = 200

Luego la función:

Estimar_AUC_lightgbm <- function(x)

entrena cada combinación del Grid Search y recupera:

AUC <- modelo_train$record_evals$valid$auc$eval[
  [modelo_train$best_iter]
]

niter <- modelo_train$best_iter

Es decir:

AUC    -> métrica de validación del modelo
niter  -> mejor iteración de boosting

Después el notebook evalúa las combinaciones del Grid y guarda:

tb_nueva[, c("AUC", "num_iterations") :=
  Estimar_AUC_lightgbm(.SD),
  by = 1:nrow(tb_nueva)
]

La tabla del Grid también se escribe en:

tb_grid_search_01.txt

Finalmente se ordena por AUC y se conserva el ganador:

setorder(tb_nueva, -AUC)

PARAM$out$lgbm$AUC <- tb_nueva[1, AUC]

PARAM$out$lgbm$mejores_hiperparametros <-
  as.list(tb_nueva[1])

De ahí salen:

AUC
num_leaves
min_data_in_leaf
num_iterations / niter

que más tarde recupera el script p12_04_integrar_resultados.py.

5.1 Estabilidad de la ganancia: desvío estándar y coeficiente de variación

Como el título del Problema #12 habla de estabilidad, no alcanza con mirar solamente la ganancia media.

Dos escenarios pueden tener una ganancia media parecida, pero uno puede variar mucho más que el otro entre semillas.

Por eso usamos dos medidas:

SD = desvío estándar de la ganancia
CV = coeficiente de variación

El coeficiente de variación se calcula como:

CV = SD / media × 100

y permite expresar la variabilidad en relación con el nivel medio de ganancia.

Estabilidad de la ganancia entre semillas
Escenario Ganancia media SD CV (%) Orden de estabilidad
3 10% 20.744 1.485 7.2 1
4 5% 20.258 1.549 7.6 2
1 100% 20.904 1.847 8.8 3
2 40% 20.924 1.915 9.2 4
5 1% 20.522 2.566 12.5 5

5.1.1 Cómo interpretar el CV

Como referencia orientativa —no como una regla universal—:

CV más bajo  -> comportamiento más estable entre semillas
CV más alto  -> mayor variabilidad relativa entre semillas

Con las 12 semillas integradas, el escenario con menor variabilidad relativa es 10%, con un CV aproximado de 7.2%.

El escenario con mayor variabilidad relativa es 1%, con un CV aproximado de 12.5%.

La lectura importante para el P12 es la siguiente:

No buscamos solamente una ganancia alta; buscamos una ganancia alta que además sea estable entre semillas.

Por eso puede ocurrir que un escenario tenga una media muy atractiva pero sea menos confiable si esa media está sostenida por una o dos semillas excepcionales.

Con las 12 semillas integradas, el escenario 1% puede alcanzar una ganancia alta en algunas corridas, pero presenta la mayor variabilidad relativa. En cambio, 10% muestra el menor CV y, por lo tanto, la mayor estabilidad relativa de ganancia entre los cinco escenarios.

Esto responde directamente a una parte central de la pregunta de “Estabilidad del modelo predictivo frente al Undersampling”.

14.4.3 Qué significa realmente el p-value

El p-value no indica cuál escenario es mejor y tampoco significa que un escenario sea “más certero”.

En nuestro Wilcoxon, la hipótesis nula puede expresarse de manera simple como:

Entre el escenario A y el escenario B no existe una diferencia sistemática de ganancia entre semillas.

Entonces:

p-value pequeño
      |
      v
mayor evidencia contra la hipótesis nula
      |
      v
hay indicios de que A y B se comportan de manera diferente

p-value grande
      |
      v
no hay evidencia suficiente para afirmar
que A y B tengan una diferencia sistemática

Por lo tanto:

un p-value más cercano a cero NO significa que esa fila sea “la mejor”.

Para saber hacia qué escenario apunta la diferencia hay que mirar también:

A gana
B gana
Empates
Mediana delta

La dirección se interpreta así:

Mediana delta > 0 -> favorece A
Mediana delta = 0 -> no aparece una dirección central clara
Mediana delta < 0 -> favorece B

El p-value original indica qué tan compatible resulta ese patrón con la hipótesis de “no diferencia sistemática”.

14.4.5 ¿Qué es el p-value Holm?

En este trabajo hacemos 10 comparaciones todos contra todos.

Cuantas más pruebas realizamos, mayor es la probabilidad de obtener algún p-value pequeño simplemente por azar.

La corrección de Holm hace el criterio más exigente para controlar este problema de comparaciones múltiples.

Conceptualmente:

1 comparación
     |
     v
menor riesgo de falso positivo

10 comparaciones
     |
     v
mayor riesgo de encontrar algún p pequeño por azar

corrección Holm
     |
     v
criterio más exigente

Para 40% vs 5%, el valor sin corrección es 0.0992, mientras que el valor ajustado por Holm es 0.9922.

Si el p-value original fuera menor a 0.05, pero el valor Holm fuera mayor, la lectura correcta sería:

existe una señal descriptiva interesante, pero todavía no alcanza para declararla estadísticamente significativa después de considerar las diez comparaciones simultáneas.

La pregunta central no es:

“¿Qué fila tiene el p-value más bajo?”

La pregunta es:

¿Hasta cuánto podemos reducir los datos sin deteriorar de manera relevante y estable el modelo?

Con las 12 semillas integradas, la interpretación se realiza sobre el conjunto completo actualmente disponible:

  • las comparaciones son pareadas y usan 12 pares por escenario;
  • pueden existir empates o diferencias iguales a cero;
  • el Wilcoxon se interpreta junto con la magnitud y dirección de las diferencias;
  • la conclusión no se decide únicamente por el p-value, sino también por dispersión, AUC y ahorro de recursos;
  • si en el futuro se incorporaran nuevas semillas, el informe se recalcularía automáticamente sin cambiar la metodología.

El p-value Holm se conserva como información adicional porque estamos realizando diez comparaciones simultáneamente. No reemplaza el criterio que finalmente indique el profesor para el trabajo.

19.1 Idea fundamental

No buscamos elegir el escenario con el número más alto de una corrida aislada.

Buscamos determinar, mediante varias semillas del mismo experimento, hasta qué nivel puede reducirse la información de entrenamiento manteniendo un comportamiento suficientemente estable, y cuánto recurso computacional se ahorra a cambio.

Este R Markdown funciona como documento de análisis y control reproducible: los scripts producen los datos; el informe los ordena, los grafica, ejecuta las comparaciones estadísticas y conserva la trazabilidad de cómo llegamos a cada conclusión.

19.2 Lectura con las 12 semillas integradas

La evidencia conjunta de las 12 semillas muestra el siguiente patrón de trabajo:

La conclusión integrada del análisis actual es:

Con las 12 semillas analizadas, el escenario 10% aparece como el compromiso más equilibrado entre ganancia, estabilidad, AUC y costo computacional. La ganancia económica no muestra diferencias estadísticamente significativas entre los escenarios en las diez comparaciones de Wilcoxon, pero el AUC se deteriora progresivamente al aumentar el undersampling y el escenario 1% presenta la mayor variabilidad relativa. Bajar de 10% a 5% o 1% reduce algo más los recursos, pero ese ahorro adicional debe evaluarse frente a la pérdida de AUC, la menor ganancia media observada en 5% y la mayor inestabilidad observada en 1%.

Esta conclusión resume el análisis completo del conjunto SEM1..SEM12 actualmente disponible. Si en el futuro se incorporaran nuevas semillas, el informe se recalcularía automáticamente y la conclusión debería actualizarse con esa nueva evidencia.
